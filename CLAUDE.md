# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A single-page "Interactive Treasure Box Game" — click one of three chests, one hides treasure (+$100), the other two hide a skeleton (-$50). Built with React 18 + TypeScript + Vite, styled with Tailwind CSS v4, animated with `motion` (Framer Motion), and scaffolded from a Figma Make / shadcn-style export (hence the `src/components/ui` library and `src/components/figma` helper, most of which is unused by the current game).

## Commands

```bash
npm install      # install dependencies
npm run dev      # start Vite dev server on http://localhost:3000 (auto-opens browser)
npm run build    # production build to ./build
```

There is no lint, typecheck, or test script configured (no `tsconfig.json`, no ESLint config, no test framework). TypeScript types are stripped by `@vitejs/plugin-react-swc` at build time but are **not checked** — don't rely on `npm run build` to catch type errors.

## Architecture

- **Entry point**: `index.html` → `src/main.tsx` → `src/App.tsx`. Nearly all game logic and markup lives in the single `App.tsx` component (box state, scoring, win/loss detection, animations) — there is no router, state manager, or backend.
- **Game state**: `App.tsx` holds an array of 3 `Box` objects (`{ id, isOpen, hasTreasure }`) in `useState`. `initializeGame` randomly assigns the treasure box on mount and on reset. `openBox` flips a box open, adjusts score, and ends the game once the treasure is found or all boxes are opened.
- **Assets**: images in `src/assets/`, sound effects in `src/audios/` (imported directly into `App.tsx` as ES modules, resolved by Vite).
- **`src/components/ui/`**: a large shadcn/ui-style component library (accordion, dialog, carousel, etc.) generated by the Figma Make export. Only `button.tsx` is currently used by the game; the rest is available but unused — safe to draw from for new UI, safe to ignore otherwise.
- **`src/components/figma/ImageWithFallback.tsx`**: fallback `<img>` wrapper that swaps in a placeholder SVG on load error. Part of the Figma Make scaffold.

### Versioned imports and the Vite alias map

Files under `src/components/ui/` import dependencies with version suffixes baked into the specifier, e.g.:

```ts
import * as DialogPrimitive from "@radix-ui/react-dialog@1.1.6";
import { XIcon } from "lucide-react@0.487.0";
```

`vite.config.ts` maps each of these versioned specifiers to the real (unversioned) package via `resolve.alias`. If you add a new shadcn/ui-style component that imports a package this way, either add a matching alias entry in `vite.config.ts` or rewrite the import to the normal unversioned form — otherwise Vite will fail to resolve it. New code you write outside of this scaffold should just use normal unversioned imports.

### CSS: two stylesheets, only one wired up

- `src/index.css` is the file actually loaded (via `main.tsx`) — but it is a **pre-compiled Tailwind v4 output file checked into source**, not a source file processed by a Tailwind build step. There is no `tailwindcss`/`postcss` devDependency and no Tailwind Vite plugin, so nothing regenerates it. If you use a Tailwind utility class that isn't already present in `index.css`, it will silently not render. When adding new Tailwind classes, verify the utility already exists in `index.css` (grep for the class) or add the missing CSS rule by hand.
- `src/styles/globals.css` defines the intended design-system approach (CSS custom properties for theme colors, `@theme inline`, dark-mode variant via `.dark`) but **is not imported anywhere** — it's leftover scaffold, currently dead code.
- `src/guidelines/Guidelines.md` is an empty template (commented out) for project-specific design guidelines — nothing is currently filled in.

### Path alias

`@` resolves to `./src` (configured in `vite.config.ts`).
